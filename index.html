Container vs VM

Containers share the host OS kernel, making them lightweight and fast. VMs virtualise the entire hardware stack — heavier but fully isolated.

Key Components

  • Dockerfile — Blueprint to build an image
  • Image — Read-only snapshot of a container
  • Container — Running instance of an image
  • Registry — Image storage (Docker Hub)
  • Volume — Persistent data storage
  • Network — Container communication layer

Sample Dockerfile — Nginx Web Server

copy
FROM nginx:alpine

# Set working directory
WORKDIR /usr/share/nginx/html

# Copy static site files
COPY ./public .

# Expose port 80
EXPOSE 80

# Default command
CMD ["nginx", "-g", "daemon off;"]

Docker Compose — Full Stack Example

copy
version: '3.9'

services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "http://localhost"]
      interval: 30s
      retries: 3
    restart: unless-stopped
    networks:
      - webnet

  app:
    build: ./app
    environment:
      - NODE_ENV=production
    depends_on:
      - db
    networks:
      - webnet

  db:
    image: mysql:8
    volumes:
      - db_data:/var/lib/mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASS}
    networks:
      - webnet

volumes:
  db_data:

  webnet:
